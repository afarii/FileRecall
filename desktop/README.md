# FileRecall Desktop (v0.4 MVP)

Windows 桌面端支持本地文件索引，以及由 Chrome 扩展发起的下载记录同步。

## 本地启动

要求：Windows 10/11、Node.js 22.13+、npm。

```powershell
cd desktop
npm ci
npm run dev
```

生产模式预览：

```powershell
npm run build
npm start
```

自动化测试：

```powershell
npm test
```

## 已实现

- 用户手动选择文件夹后递归索引普通文件，跳过符号链接。
- 索引存入应用用户数据目录的 SQLite 数据库，重启后保留。
- 搜索文件名或路径，最多返回 500 条结果。
- 重新扫描时，对已消失的文件保留历史记录并显示「已丢失」。
- 当子目录读取失败或发生其他跳过时，扫描视为不完整，不据此把旧记录标记为丢失。
- 在 Windows 资源管理器中显示仍然存在的文件。
- 已授权目录可点击「停止索引」，后续重扫将跳过该目录，已有历史仍可搜索。父目录仍被授权时，其中的子目录依然在扫描范围内。
- 「停止并清除历史」可撤销该目录及子目录授权，并清除这些路径下的数据库记录，磁盘文件保留。已停止目录也提供「清除历史」。操作使用事务，失败时恢复授权与记录。若父目录仍获授权，需先停止父目录索引，以免再次自动建立记录。
- 父子目录同时授权时，完整重扫按实际路径范围判定丢失文件。
- SQLite 写入失败会报告错误并暂缓缺失判定；应用退出时等待当前扫描结束后关闭数据库。
- 单实例运行，重复启动会聚焦已有窗口；启动入口清除继承的 `ELECTRON_RUN_AS_NODE`。
- 应用启动时补扫授权目录，原生文件事件触发对应目录重扫。连续事件默认合并 500 毫秒，持续事件最长等待 2 秒后安排扫描。
- 每 30 秒校验授权目录、重建监听并重扫，补偿事件丢失、监听错误和目录暂时离线。访问失败保留原有状态，恢复后自动重试。
- 自动扫描、手动重扫、停止索引和清除历史共用串行队列。停止索引会释放监听，清除历史会等待当前扫描结束，应用退出会等待已接受的操作结束。
- 界面显示目录监控状态和错误，索引变化会自动刷新当前搜索结果。SQLite 数据库及其 WAL/SHM 文件排除在自身索引与事件触发范围外。

## Windows 验收步骤

1. 准备专用目录，放入中文文件名和含 `%`、`_` 的文件，并创建子目录。
2. 运行 `npm ci`、`npm test`、`npm run build`、`npm start`。
3. 点击「添加文件夹」并选择专用目录，核对扫描数量。取消选择应保持已有目录和记录。
4. 搜索中文文件名、完整路径和 `%`，核对字面匹配结果。
5. 点击「在文件夹中显示」，检查资源管理器是否打开正确目录并选中文件。
6. 删除专用测试文件，点击「重新扫描」，确认旧记录标记「已丢失」且定位按钮禁用。恢复同一路径后重扫，应恢复「存在」且保持一条记录。
7. 关闭并重启应用，核对授权目录和存在、丢失记录仍保留。
8. 将专用目录临时改名后重扫，应显示失败原因并保留历史状态。恢复目录名后重试。
9. 点击「停止索引」并重启，核对授权已撤销、历史仍可搜索。重新添加相同目录后应可继续扫描。
10. 在授权目录中新增、修改、删除专用文件，观察结果自动更新；持续写入后核对最终大小。变化触发对应目录重扫，大目录完成时间取决于文件数量。
11. 关闭应用后新增文件，重启应通过启动补扫发现。临时改名目录后等待最多 30 秒加扫描时间，应显示等待重试；恢复目录后应自动恢复监控。
12. 停止索引后新增文件，应保持旧历史且停止更新。「停止并清除历史」确认后应移除该目录及子目录记录，其他目录保留；重启后确认清除结果。

## 当前限制与计划

- 当前监控采用事件触发的目录重扫和 30 秒周期校验，大目录可能有更新延迟。应用关闭期间的变化在下次启动补扫中处理。
- 文件重命名在本阶段会作为旧路径「已丢失」和新路径「存在」两条记录显示。
- 本地全文搜索和语义检索安排在后续版本。
- 默认只扫描授权文件夹；不扫描系统全盘、不上传文件信息。
- 使用 Node 内置 `node:sqlite`，当前为实验性 API；运行时可能出现实验性功能警告。
- 本阶段尚未生成 Windows 安装包，须先通过 Windows 实机验证。

## 在 Windows 同步 Chrome 下载

1. 安装 Node.js 24 或更高版本。在 Chrome 的扩展程序页面开启开发者模式并加载仓库根目录，或重新加载已从同一目录安装的 FileRecall。复制页面显示的扩展 ID。
2. 在仓库根目录运行以下命令。连接程序由 Windows .NET Framework 编译器构建，并注册到当前 Windows 用户。生成文件保存在 `desktop/native`。

   ```powershell
   .\desktop\native\register-chrome.ps1 -ExtensionId <扩展ID>
   ```

3. 打开 Chrome 中 FileRecall 的历史页，点击「同步到 FileRecall 桌面端」，首次同步时授予本地连接权限。同步传送已完成的下载、原路径和保存的页面来源，桌面关闭时也能接收。同步中断后可再次点击，已收到的记录会按 Chrome 配置文件和下载标识更新。
4. 启动桌面端，打开「浏览器下载」。已打开此页时可以点击「刷新」。按文件名、网站域名或页面标题搜索，查看原路径和下载时间。
5. 点击「打开来源页面」，由系统默认浏览器打开可信来源。候选与未知来源各有状态标签。Chrome 中的来源更正会在再次同步时更新。

同步记录保存在 FileRecall 应用数据目录的 `browser-downloads.sqlite`。下载页显示的文件状态描述原路径，文件移动后原路径也可能显示丢失。同步接受 Windows 盘符路径。

解除连接时，可删除当前用户的专用注册项。

```powershell
reg.exe delete HKCU\Software\Google\Chrome\NativeMessagingHosts\com.filerecall.desktop /f
```

验收时，先同步一个来源已确认的测试下载，再移走或删除测试文件并按网站搜索。核对原路径状态，点击「打开来源页面」。另同步一个未确认的候选并核对状态。关闭桌面后再同步一次，重启桌面确认记录可查询且没有重复。
