## 性能诊断（开发分支）

遇到输入卡顿、MFT 建索引时“未响应”等情况，打开「设置 → 性能诊断」，点击「刷新指标」查看最近 10 秒采样的主线程延迟、后台索引延迟、CPU 使用量和内存占用。「复制性能摘要」会复制最近 24 组数值采样。

客户端也会在本机 `%APPDATA%\\filerecall-desktop\\performance-diagnostics.jsonl` 追加记录；即使 UI 暂时卡顿，恢复后采样仍会写入。日志大小超过约 1 MiB 时滚动保留。选择「定位日志文件」可直接打开所在目录。日志不包含搜索文字、文件名、文件路径和来源网址。需要提供给开发者时可先检查内容。

本次性能修复将 NTFS MFT/USN/拼音索引和普通 SQLite 查询分别隔离到工作线程；客户端版本为 v0.4.8，NTFS 为 Windows 文件名搜索主索引，旧文件元数据仍保留以支持来源、收藏和历史记录。

> 当前开发分支（PR #18）使用统一即时搜索界面：输入文件名、拼音或来源时结果自动更新；高频文件、中文首字母与常用文档优先显示。索引、授权目录、搜索热键、Chrome／aria2 连接及软件更新均已移动至「设置」。此阶段统一为 v0.4.8。

## v0.5.0-beta.1：统一搜索里的「历史与找回」

搜索支持多词及拼音与扩展名组合（如 `sy pdf`、`pdf sy`）。重复关键词必须对应独立的匹配位置。快速前缀搜索先显示结果；少量匹配时停顿约 300 ms 后在独立线程补查文件名中间的关键词，避免阻塞输入。USN 增量更新会刷新当前搜索。Beta 版请验证下载、重命名和移动后的搜索体验。

输入文件名、来源网站、下载页面标题或下载线索，当前文件由 NTFS 主索引即时返回；Chrome 和 Motrix 历史在独立后台线程中补充，避免影响文件名搜索的响应速度。

匹配到已有文件时，相关历史下载与已丢失记录收在「查看相关下载与历史记录」区域，可按需展开；只匹配到历史记录时，自动显示「历史与找回」。下载记录保留独立证据；同一路径曾被覆盖时，仍需用户核对是否为同一文件。对于有可信来源的历史下载，详情提供「查看来源，尝试找回」，打开原网页或已记录的下载地址，由用户决定是否重新下载。

文件原路径不可访问但状态无法核实时显示「状态未确认」，防止将离线磁盘上的文件误判为已删除。已经存在的 v0.4.8 实时搜索、收藏和来源确认数据保持不变。本功能位于独立开发分支，待 Windows 实机验证。

## v0.4.8：统一文件名搜索与文件元数据

Windows 本地固定 NTFS 磁盘的文件名、路径与拼音只从 NTFS 主索引检索，已授权文件夹的记录用于补充文件来历、收藏、备注与正文信息。旧 `files.sqlite` 会安全保留，支持历史已丢失记录、非 NTFS 磁盘及旧数据迁移。使用时只有一个搜索框，收藏通过搜索框旁的「☆ 收藏」切换。

### NTFS 文件名主索引

首次索引直接读取 MFT 文件记录号、父目录号和文件名，随后在本机根据目录关系重建路径。扫描阶段无需逐目录打开文件或检查 ACL；已经扫描且能够解析父目录的文件可以立即通过主搜索框查询。每个磁盘分时扫描，SQLite 保存扫描位置，意外退出后可以接续；完成后使用 USN 日志追赶扫描期间的文件变动。

**隐私与访问权限：** 经 Windows UAC 授权的全盘索引会记录隐藏文件、系统文件以及部分普通账户无法读取内容的文件的名称与路径。索引文件保存在当前用户的 `%APPDATA%\\filerecall-desktop`，不会上传；打开文件或读取正文仍遵循 Windows 权限控制。共用电脑请注意本地索引元数据的可见性。

性能方面，CI 的合成数据库性能测试不代表真实磁盘首次扫描时间，需要在实际 Windows 设备上测量首次可搜索时间、整盘完成时间和资源占用。

## v0.4.6：中文文件名拼音搜索

主搜索框在普通文件名和路径搜索之外，新增拼音查询：`实验报告.pdf`、`shiyanbaogao`、`sybg`、`pdf sybg`、`sy` 均可匹配同一文件。多个词之间用空格分隔，按“同时匹配”筛选；搜索保留大小写不敏感、中文原名及原有历史记录。

索引在本机计算文件名全拼与每个汉字拼音首字母。升级后，旧版 SQLite 索引后台分批生成搜索键；全盘 NTFS 索引和用户授权目录索引均适用。此功能只索引文件名，不上传目录和文件内容。短查询（例如 `sy`）可能匹配大量文件，可继续输入更长的首字母缩写或扩展名缩小范围。

# FileRecall v0.4 使用手册

FileRecall 可以搜索你选定目录中的文件，也能收纳 Chrome 和 Motrix／aria2 的下载记录。找到文件后，点开详情查看当前位置、原路径和已知来源。

## 1. 安装与首次使用

1. 在 [预览版安装包](https://github.com/afarii/FileRecall/releases/tag/desktop-preview) 里打开最新成功的构建，下载并解压 `FileRecall-Windows-x64`，运行其中的 `FileRecall-Setup-*-x64.exe`。安装包适用于 Windows 10／11 x64，内置运行环境，目前为未签名的验收版。
2. 打开 FileRecall，点「设置 → 授权目录与正文搜索 → 添加文件夹」。先选一个几份文档所在的目录，等待界面显示「自动监控中」。
3. 回到「搜索」，输入文件名的一部分。点中文件后，可在右侧详情打开文件、在资源管理器定位或复制路径。

从 v0.4.0 升级时，右键托盘图标选择「退出 FileRecall」，再用 v0.4.1 安装包覆盖安装。索引和设置保存在当前 Windows 用户的 `%APPDATA%\filerecall-desktop`。

从 v0.4.1 起，Windows 安装版在运行期间会检查预览版更新，缩到托盘时也会检查。也可以从顶部「软件更新」手动检查。看到新版时，依次点「下载新版」和「重启并安装」。客户端只向 GitHub 请求更新信息和安装包。

## 2. 搜文件和正文

| 我记得什么 | 在哪里搜 |
| --- | --- |
| 文件名、路径、下载网站 | 直接输入搜索框，文件与下载来源自动合并显示。 |
| 文件里的一句话 | 在「授权目录」开启「搜索文件正文」，等待重新扫描，再输入原句。结果会标明「正文匹配」。 |
| 大意或同义描述 | 在「设置 → 本地 AI 搜索」切换，开启正文索引后下载本地模型。 |
| 自己写过的标签或备注 | 打开文件详情中的「收藏、备注和标签」，保存后可按文字搜索，也可用「收藏」筛选。 |

正文支持 UTF-8 TXT、Markdown（不超过 128 KiB），以及带文字层的 PDF 和 `.docx`（文件不超过 20 MiB）。PDF 读取前 100 页。扫描件需先有可选中的文字层。

例如在测试目录的 Markdown 写下「第四季度预算」，启用正文索引后，可以先搜原文，再试语义描述「冬天的开销计划」。AI 比较最近索引的最多 500 份文档，每份取最多三段。语义匹配表示内容相近，文件来历仍需单独核对。

客户端运行时，按 `Ctrl+Shift+Space` 可从其他窗口唤出搜索。可在「设置 → 搜索热键」修改。搜索框里按方向键下移到结果，按回车查看详情。

在 Windows 点窗口右上角的「×」会隐藏到系统托盘，热键、目录监控和 Motrix 同步继续运行。可按热键或点任务栏通知区域的 FileRecall 图标重新打开窗口。图标也可能在「^」的隐藏图标区。要完全退出，请右键图标，选「退出 FileRecall」。

从 v0.4.2 起，自动监控只更新收到变更通知的文件或子目录。后台每 30 秒检查授权目录是否仍可用，每 30 分钟补扫一次健康目录，以找回文件系统偶尔漏发的通知。监听中断时会自动重试，也可以在「授权目录」手动重新扫描。

### 自动搜索本地 NTFS 整盘

FileRecall 启动时自动发现本地固定 NTFS 磁盘，Windows 授权后在后台建立 MFT 文件名索引，随后使用 USN 日志增量更新。已有索引在等待 Windows 授权时仍可搜索缓存的文件名和路径，重新连接后才能核验并定位文件。主搜索框可同时查找整盘文件、授权目录文件和下载记录；磁盘索引由后台自动管理。正常情况下无需操作；只有首次授权失败或旧版本遗留暂停状态时，搜索界面才显示恢复按钮。

打开文件详情时按需读取 Zone.Identifier 中的 MOTW 来源标记，ReferrerUrl 和 HostUrl 作为待核对线索显示，默认不会自动打开或确认来源。整盘仅索引文件名和路径，正文搜索仍按用户授权目录运行，索引保存在本地。

### 旧版独立整盘入口

FileRecall 自动管理已发现的固定 NTFS 磁盘，无需手动逐盘添加。首次索引读取文件名和目录关系，并保存在本机；后续使用 NTFS USN 增量更新。点击统一搜索结果可查看路径、来源及收藏等信息。

首次读取 NTFS 文件表，随后只更新变更日志中的文件。助手连接正常时，同盘中能使用 USN 的授权目录跳过 30 分钟补扫。退出 FileRecall 也会退出助手，下次启动自动连接并复用既有索引。磁盘换卷时需要重新添加，日志断档时会自动重建该盘的快速索引。

## 3. 同步下载记录

### Chrome 直接下载

1. 首次安装扩展时，在 `chrome://extensions` 打开「开发者模式」，点「加载已解压的扩展程序」，选择含 `manifest.json` 的 FileRecall 目录。已安装用户更新原目录后，点现有扩展的「重新加载」以保留记录。
2. 复制 Chrome 扩展管理页显示的 FileRecall 扩展 ID。打开 Windows 安装版「设置 → Chrome 设置」，粘贴 ID，点「保存连接」。
3. 在 Chrome 点 FileRecall 扩展图标，打开「下载历史」，点「同步到桌面」。首次操作需允许本地连接。回到 Windows 窗口，在统一搜索框输入文件名或来源网站。

Chrome 扩展里的「导入旧下载记录」可补录 Chrome 仍保留的历史，每批最多 100 条。旧记录的来源从「未知」开始。可以在扩展详情中核对候选或补充网页，之后再次同步。

### Motrix／aria2 接管下载

1. 保持现有的浏览器接管设置，并启动本机 Motrix 或 aria2。
2. 在 FileRecall 的「设置」中点「Motrix／aria2」。填下载器设置中显示的 RPC 端口。FileRecall 预填 `16800`，使用你的实际端口。如果下载器设有 RPC 密钥，也在此输入。
3. 点「连接并同步」。从浏览器下载测试文件，交给 Motrix 完成，再到 FileRecall 点「立即同步」，或等下一次约 30 秒的自动同步。直接在统一搜索框输入文件名或下载地址。

FileRecall 读取本机 RPC 中仍保留的最近 500 个已停止任务，导入其中已完成的文件。下载器报告唯一已使用的 HTTP(S) 直链时，详情会显示「打开下载地址」。网页来源保留为未知。重复同步会去重，断开连接会保留已导入记录。

## 4. 核对文件来历

1. 找到一个本地文件，点开详情里的「文件来历」。名称或路径吻合的下载记录会列为候选。
2. 核对原下载路径、时间和来源。确定是同一份文件时选「确认是同一文件」。也可以「排除」，之后可撤销。
3. 文件在同一磁盘卷的已授权目录间改名或移动后，搜索旧名并点「定位现址」。文件删除后可通过旧文件名搜索到历史记录。详情中有可信网页或已记录的下载地址时，可打开原网页或直链。

## 5. 管理授权与常见问题

| 遇到的情况 | 怎么处理 |
| --- | --- |
| 想停止扫描并保留历史 | 在「授权目录」点「停止索引」。历史仍可搜，退出授权范围的文件正文会从索引移除。父目录仍在授权时，子目录也仍在扫描范围内。 |
| 想清掉某个目录的本地索引历史 | 点「停止并清除历史」，或在已停止的目录旁点「清除历史」。磁盘文件会保留。独立同步的 Chrome 和 Motrix 下载记录仍可在统一搜索框中查找。 |
| 文件已经移动，结果还显示旧状态 | 等待自动监控更新，或在「授权目录」点「重新扫描」。跨卷移动、重复副本或证据不足时，历史可能继续显示丢失或候选。 |
| Chrome 同步成功，但桌面没有显示 | 回到桌面窗口后重新搜索，也可在「Chrome 设置」点「刷新下载记录」。检查扩展 ID 和本地连接权限。 |
| Motrix 没看到记录 | 确认下载器正在运行、任务已完成，并核对 RPC 端口和密钥，再点「立即同步」。已从下载器清理且从未导入的任务无法补录。 |
| AI 搜不到或提示暂无可用正文 | 确认已下载模型、已开启正文索引，并且扫描完成。可返回普通搜索尝试文件名或确切短语。 |
| 热键冲突 | 在「设置 → 搜索热键」改用另一个组合，例如 `Ctrl+Alt+F10`。新组合保存成功后才会替换原来的热键。 |


## v0.5.0-beta.3：全盘文件与下载来源关联（测试中）

在 NTFS 文件详情的「下载来源」中核对 Chrome / Motrix 下载记录，点击「确认是同一文件」保存关联。通过统一搜索框查询来源网站或下载记录后，打开历史记录可定位同卷移动或重命名后的文件。文件身份须由卷标识、NTFS 文件引用及实时文件元数据共同核验，路径一致仅用于候选推荐。若无法验证现址，保留已确认的历史关联；可信来源仍可尝试打开。当前仅在用户打开详情或定位已确认关联时读取文件身份，不全盘扫描来源元数据；跨卷复制以及缺失的历史下载来源仍需后续处理。


## v0.5.0-beta.4：自动来源记忆（测试中）

桌面端通过 NTFS 变更事件低速读取新建、重命名及发生备用数据流变更的文件的 Windows 来源标记。每 250 毫秒至多处理一个待采集文件，队列最多 512 项，读取失败时延迟重试；打开现有文件详情也可按需采集。首次索引不会遍历所有文件读取 ADS。来源网址与文件身份保存在本机 motw-memory.sqlite 中，不上传。用户可在搜索框输入来源域名/网址及文件名关键词，定位仍可验证的文件；已观察到删除事件的记录保留为历史来源，离线或无法验证的文件显示状态未确认。Windows 来源标记可能被修改，打开链接前应核对。仅保留成功观测到的来源；过载、未写入 MOTW、权限不足、捕获前删除、跨卷复制以及日志缺口等情况下可能没有来源记录。删除历史记忆的独立管理界面尚未提供。
