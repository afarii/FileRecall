# FileRecall v0.4.5 — 软件工程阶段交付记录

> 状态：Windows 预览版开发分支，正式合并和 Release 由维护者验收后决定。本文只记录代码、合成测试和公开 CI 结果；本机真实文件名、路径、下载历史和数据库均留在用户设备。

## 1. 项目目标与需求

FileRecall 面向“记得文件线索但忘记文件位置或来源”的场景，通过本地文件索引、下载来源证据与历史记录实现文件定位和来源找回。

| 编号 | 验收需求 | 当前实现 |
|---|---|---|
| R-01 | 启动后自动发现本地固定 NTFS 磁盘，后台建立文件名索引 | Windows CIM 盘符发现，UAC 授权后的 MFT 枚举 |
| R-02 | 文件变更自动更新，重启后复用索引 | USN 日志游标、重建与异常恢复；离线搜索缓存结果标注待核验 |
| R-03 | 统一入口搜索文件名、已授权正文及下载记录 | 主搜索框组合本地目录、整盘 NTFS、Chrome、Motrix/aria2 结果 |
| R-04 | 可靠保留来源证据，文件移动或删除后可追溯 | Chrome 下载记录与身份关联；已授权目录的 MOTW 证据按文件身份缓存 |
| R-05 | 只展示有证据的来源信息 | 来源确认、候选、未知分级；MOTW 显示为待核对线索 |
| R-06 | 所有用户文件与索引保存在本地 | SQLite 用户数据目录、无上传机制；发布仅包含源码与构建产物 |
| R-07 | 自动化验证、可安装及更新 | Windows GitHub Actions、NSIS x64、可选预览更新通道 |

## 2. 架构与关键设计

- **Electron / React / TypeScript**：主界面与搜索交互。
- **Node.js / SQLite**：授权目录、文件历史、下载证据、人工决策和本地搜索。
- **C# NTFS 只读助手**：受 Windows UAC 保护，读取 MFT 与 USN；按照普通用户目录访问权限筛选可见结果。
- **Chrome Native Messaging**：导入浏览器下载记录及已知页面证据。
- **aria2 JSON-RPC**：只连接本机下载器，来源网页与下载直链分别标注。
- **本地离线模型**：经用户主动下载后支持文档语义检索。

关键约束：优先准确性，证据不足时显示未知或候选。整盘索引默认只保存文件名与路径；正文和 AI 搜索须由用户选择授权目录。MOTW 读取限定 8 KiB，接受 HTTP(S) URL，作为本地线索存储与展示，不自动确认为可靠来源。

## 4. 自动化测试与性能记录

### 功能测试

- Chrome 扩展回归测试覆盖下载记录、来源更正、去重和历史查询。
- 桌面测试覆盖扫描、目录离线恢复、路径移动、来源绑定、MOTW 历史保留、SQLite 清理和缓存行为。
- 新增的 MOTW 变更测试验证：即使文件主内容修改时间未变化，文件事件仍会重新读取 Windows 来源标记。
- 打包后执行 Chrome Native Messaging 连接程序测试。

### 合成文件名搜索基准

Windows CI 中使用 **60,000 条纯合成文件名**、内存 SQLite 和固定查询集合。一次测量：

| 指标 | 结果 |
|---|---:|
| 合成索引建库时间 | 676.2 ms |
| SQLite 数据量 | 6.23 MiB |
| 高频前缀查询 P95 | 2.846 ms |
| 选择性子串查询 P95 | 5.037 ms |
| 无结果查询 P95 | 4.001 ms |
| 中文子串查询 P95 | 0.301 ms |
| 路径查询 P95 | 0.327 ms |

来源：[Windows CI #60](https://github.com/afarii/FileRecall/actions/runs/45144185220)，\`node desktop/bench/ntfs-catalog.mjs\`。这些数值适用于合成样本和 CI 环境；真实整盘性能、低功耗表现、冷启动、异常重启仍需在实际 Windows 设备上验收。前缀快路径受 \`ntfs_item_name\` 索引加速；一般子串查询依然使用 SQLite \`instr()\`。

## 5. Windows 人工验收清单

建议使用无个人资料的专用测试目录和测试磁盘。执行过程记录通过/失败、操作步骤与匿名汇总，不截取私人文件名或路径。

- [ ] 全新安装与旧版覆盖安装：应用正常打开，原本地数据库继续可读
- [ ] 启动自动索引：枚举固定 NTFS 磁盘，UAC 取消后有重试入口
- [ ] 索引进度：首次建库完成后主搜索找到合成文件；二次启动可先查缓存
- [ ] 文件变化：新增、删除、移动与目录重命名后索引更新；断开 USN 后恢复
- [ ] 来源历史：人工构造 MOTW，读取后删除文件仍显示历史线索
- [ ] 证据隔离：用新文件占用原路径，旧来源不附着到新文件
- [ ] 撤销与清除：停止磁盘索引，清除授权目录历史后 MOTW 证据一并清理
- [ ] 性能记录：首次 MFT 建库耗时、峰值内存、数据库大小、典型查询 P95
- [ ] Chrome/Motrix：同步及人工来源确认仍按预期工作
- [ ] 升级与卸载：\`desktop-preview\` 更新流程、托盘关闭、数据保留行为

## 6. 当前限制与后续冻结建议

1. **UAC**：当前 NTFS 助手随应用退出而终止。每次重新启动时 Windows 仍可能请求提升权限；持续免 UAC 需要单独设计并安全审查受限 Windows 服务。已有索引在助手断开时仍可查看缓存，定位操作等到重新验证后开启。
2. **MOTW 历史覆盖**：已授权目录在扫描过程中捕获来源标记并持久化。整盘搜索结果的 MOTW 目前按需读取，尚未对整个磁盘逐文件扫描来源数据，以避免大量额外磁盘 I/O。
3. **扩展与签名**：Windows 安装包仍为未签名预览版。
4. **正式发布条件**：完成上一节的 Windows 实机验收，核对升级和隐私，确认后再解除 Draft 状态并发布正式版本。

建议在 v0.4.5 之后冻结主要功能，整理需求说明、设计文档、测试报告、项目计划与课堂演示材料。正式交付前根据课程老师提供的具体格式要求补充封面与分工信息。
