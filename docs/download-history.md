# 下载历史界面（Issue #13）

重新加载扩展后，点击 Chrome 工具栏或扩展菜单中的 FileRecall 图标，在独立标签页打开下载历史。
页面直接读取 `chrome.storage.local` 中的 `download:<id>`，不写入、编辑或删除记录。

列表按下载开始时间倒序，时间缺失的记录放在末尾。点击一条记录打开详情抽屉；按 Esc、关闭按钮或点击抽屉外部可关闭。
支持键盘 Tab 定位记录、Enter 打开详情。窄屏下列表会调整布局。

搜索框支持按文件名、来源域名、来源页面标题进行不区分英文大小写的子串搜索（忽略搜索词首尾空白）。
`matched` 只搜索已确认上下文，`candidate` 只搜索候选上下文并保留“候选 · 未确认”标记，
`unknown` 只搜索文件名。搜索不会检索保存目录、下载 URL 或 referrer，也不修改任何记录。
结果保留原下载时间倒序，清空搜索恢复全部记录；无匹配时显示明确提示。“全部记录”计数保持为总记录数，
匹配数量通过无障碍通知播报。刷新或下载自动更新后会保留搜索词并重新计算结果。
已打开的详情继续跟随原记录更新，即使它不再命中搜索；关闭后焦点返回可见记录或搜索框。

来源显示遵循已保存的关联结果：

- `matched`：只读取 `source.context`，标为“来源已确认”。
- `candidate`：只读取 `source.candidate`，持续显示“候选 · 未确认”。
- `unknown`：不从 referrer、下载域名、文件名或残留上下文推测来源。

详情同时展示下载事件提供的原始 URL、referrer、完整保存路径和时间，以及关联原因、证据和点击快照。
缺失字段显示“未记录”；无法展示的损坏记录计数提示，原数据保持不变。外部文本通过 `textContent` 展示，只有
HTTP/HTTPS URL 可点击，外链在新标签页打开并使用 `noopener noreferrer`。不加载外部字体、脚本或网站图标。

## 自动化验证

```powershell
node --test
```

既有测试覆盖下载捕获接线、匹配和持久化；`history-view.test.mjs` 覆盖排序、异常记录、来源语义、URL 安全、
读取失败及刷新竞争。后台接线测试也检查扩展入口打开正确的页面。
搜索测试覆盖三种来源状态、大小写、空查询、无匹配、排序和只读约束，以及详情、焦点恢复和自动更新交互。

## Chrome 人工验收

1. 在 `chrome://extensions` 重新加载 FileRecall，点击扩展图标，确认打开独立历史页。
2. 有已有记录时无需打开 DevTools，即可看到文件、来源状态、时间和下载状态；最新下载排在前面。
3. 分别打开 testfile.cc 的已匹配记录、VS Code 的候选记录和未知记录。候选详情必须显示“未确认”，
   未知来源不得借用 referrer 作为来源标题；详情中仍可单独查看原始 referrer。
4. 检查完整路径、下载 URL、页面 URL/标题、点击文字、时间，以及展开后的关联原因与证据。
5. 保持历史页打开后新增下载或取消下载，记录应自动更新，也可使用“刷新记录”。
6. 用 Tab 和 Enter 打开记录，按 Esc 关闭并返回记录；缩窄窗口，确认文本不撑破页面、详情仍可关闭。
7. 用独立测试配置文件、首次安装且尚无记录时验证空状态。不要为了测试而清空日常配置中的历史。
   损坏数据、读取失败与重试由自动化测试覆盖，需要手动构造时也请使用独立测试配置。

8. 分别输入文件名片段、来源域名、页面标题，混用英文大小写，确认结果正确且时间顺序不变；
   候选结果的列表及详情均须显示“候选 · 未确认”。未知记录只能按文件名命中，不能按其下载域名或 referrer 命中。
9. 输入不存在的词，确认显示“没有找到匹配的下载记录”；清空搜索后恢复全部记录。
10. 搜索期间点击刷新、新增下载或取消下载，确认搜索词保留、结果自动更新。打开命中记录详情后触发下载更新，
    确认详情与列表正常更新、抽屉滚动位置保留；关闭详情后键盘焦点返回可见记录或搜索框。
11. 在窄屏下检查搜索框布局，用 Tab 聚焦搜索框、输入及清空搜索，再用键盘打开和关闭详情。

当前支持搜索与只读详情，没有筛选或分页。大量记录时整表读取和渲染可能变慢。
浏览器中已经错过的下载事件不会补录；显示的是保存的下载状态，不代表文件现在仍在磁盘上。
